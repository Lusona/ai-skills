# Lusona Skills

[English](README.md) | [Español](README.es.md) | [Deutsch](README.de.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md)

Lusona は、コーディングエージェントによるプロダクト開発とエンジニアリングのための 14 のスキルです。
各スキルは、変更の仕様定義、実装、レビューなど、一つの責任を担います。すべてのスキルは同じ八つの
ループ原則に従い、プロジェクトの `docs/lusona/` に記録を残し、各作業の返信を状態、根拠、次の作業で締めくくります。

Claude Code、Codex、[Cursor](INSTALL.md#cursor)、[Xcode 27 のコーディングエージェント](INSTALL.md#xcode)、[Google Antigravity App・CLI・IDE](INSTALL.md#antigravity)に対応 · チェックアウトしたソースのバージョン：**3.0.0**

> [!WARNING]
> Lusona のインストールには Vercel Skills（`npx skills@latest`）を使わず、[ホスト標準のプラグイン機能](#インストール)を使ってください。

Lusona Skills を開発した背景：[Why we built Lusona Skills](https://blog.lusona.com/blog/why-we-built-lusona-skills/)。

この README は、チェックアウトしたソースの内容を説明しています。GitHub からのインストールには、
コミットしてプッシュしたソースを使います。ローカルの変更だけでは、公開リリースにはなりません。

![Lusona の作業ループ、原則、スキルの分類](plugins/lusona/assets/workflow-loop.svg)

円は、選択、実行、確認を繰り返して作業を進める流れを示しています。現在の必要に応じてスキルを選びます。
どのスキルの後にも別のスキルを使えます。

## ループ原則

すべてのスキルは、範囲を絞った次の作業を選び、実行し、結果を確認するというループで動作します。
依頼された成果を達成するまで、この流れを繰り返します。理解が深まるにつれてシステムと設計を改善することが
目的です。すべてのスキルに適用される次の八つの原則は、
[ワークフローガイド](plugins/lusona/references/workflow-guide.md#loop-principles)で定義されています。

| ID | 原則 | 利用者にとっての意味 |
| --- | --- | --- |
| P1 | 固定の順序を設けない | エージェントは未解決の必要に応じて次のスキルを選びます。どのスキルの後にも別のスキルを使えます。一つの変更では、残っている作業に必要なスキルだけを使います。 |
| P2 | 改善を繰り返す | 各回の結果を目指す成果と比較し、事実と仮定を区別します。成果、合意済みの判断、権限、TDD レベル、根拠、不確実な点を次の回へ引き継ぎます。 |
| P3 | 過去の判断を入力として扱う | 新たな入力が合意済みの判断と矛盾しても、エージェントは入力を拒んだり判断を無視したりしません。矛盾を示し、利用者とともに判断を見直します。 |
| P4 | 失効を記録する | 置き換えられた判断には日付と情報源を記し、その理由も残します。関連記録の整合性を保ち、古い記録によって置き換え済みの選択を復活させません。 |
| P5 | 主張より根拠を優先する | エージェントは、実際に観測した確認結果だけを根拠に動作や完了を報告します。必須の確認が失敗した場合や未実行の場合は、完了にできません。 |
| P6 | 権限は利用者が持つ | 仕様書、計画、ADR、キューの状態は実装の許可にはなりません。合意済みの成果、契約、TDD レベル、影響の大きい確約を変えるには、利用者の判断が必要です。 |
| P7 | 範囲を絞った作業を続ける | エージェントは新たな指示を待たずに次の許可済み作業を行い、次の作業を変えない問いの追究をやめ、影響を受ける作業だけを一時停止します。 |
| P8 | すべての返信で次の作業を示す | 各作業の返信は、次の作業一つとその担当を示して終わります。残る作業がなければ、そのことと理由を示します。 |

## 作業を始めてスキルを選ぶ

プロジェクトに参加するとき、作業を再開するとき、何に取り組むべきかを考えるときは、**status** から始めます。
読み取れる記録と根拠を評価し、把握できた残作業をすべて挙げ、次の作業を提案します。Lusona の記録がまだない
プロジェクトでも使えます。状況確認の依頼は、実行権限を与えるものでも取り消すものでもありません。

現在の必要に合うスキルを選んでください（P1）。表の行は実行順序ではありません。目指す動作と範囲が明示された
許可済みの依頼は、**specify** を経ずに **implement** で進めます。

| スキル | 使う場面 |
| --- | --- |
| [status](plugins/lusona/skills/status/SKILL.md) | 状況、進捗、残作業、再開方法を知りたいとき |
| [explore](plugins/lusona/skills/explore/SKILL.md) | 選択する前に、方向性、選択肢、将来像を検討したいとき |
| [frame-product](plugins/lusona/skills/frame-product/SKILL.md) | プロダクトの対象者、課題、ビジョン、成果、境界が未定義または変更中のとき |
| [map-capabilities](plugins/lusona/skills/map-capabilities/SKILL.md) | 機能の充足状況、依存関係、提供順序を明確にする必要があるとき |
| [specify](plugins/lusona/skills/specify/SKILL.md) | 変更の目指す動作、範囲、受け入れ基準を定義する必要があるとき |
| [architect](plugins/lusona/skills/architect/SKILL.md) | 境界、契約、責任分担について、長期的な影響のある技術判断が未解決のとき |
| [design](plugins/lusona/skills/design/SKILL.md) | 画面、フロー、状態、関係を判断または選択するために、目に見える形にする必要があるとき |
| [implement](plugins/lusona/skills/implement/SKILL.md) | 変更の実装が許可されているとき、または計画だけが必要なとき |
| [review](plugins/lusona/skills/review/SKILL.md) | 完了前に、差分が目指す動作に合うかをレビューする必要があるとき |
| [refactor](plugins/lusona/skills/refactor/SKILL.md) | 既存コードに具体的な構造上の問題があり、動作を維持する必要があるとき |
| [investigate](plugins/lusona/skills/investigate/SKILL.md) | 原因、観測された動作、実現可能性について根拠が必要なとき |
| [measure](plugins/lusona/skills/measure/SKILL.md) | 判断に基準値、ベンチマーク、比較可能な観測結果が必要なとき |
| [experiment](plugins/lusona/skills/experiment/SKILL.md) | 方針の採用、却下、改善を判断するために試行が必要なとき |
| [batch](plugins/lusona/skills/batch/SKILL.md) | 選択したキュー項目の無人作業を許可するとき、または記録済みのバッチを再開するとき |

[ワークフローガイド](plugins/lusona/references/workflow-guide.md)に、各スキルの担当像と成果物、振り分け表、
用語を記載しています。スキルを切り替えるための新たな許可は不要で、利用者が毎回の移行を指示する必要もありません。

使用するホストでスキルを呼び出します。

- Claude Code：`/lusona:<skill>`。例：`/lusona:status`。
- Codex：スキル選択画面から Lusona のスキルを選びます。
- Cursor：Agent チャットで `/` を入力し、スキルを選びます。
- Xcode：エージェントとの会話で `/` を入力し、インストール済みのスキルを選びます。
- Antigravity App と CLI：`/<skill>`。例：`/status`。スタンドアロン IDE では **Customizations** を確認し、
  依頼の中で Lusona のスキル名を指定します。

これらのスキルを使う前に、[Lusona をインストール](#インストール)してください。依頼には、スキル名、成果または
入力となる記録、許可する範囲を示します。例：

> **status:** 現在の記録と作業ツリーから、このプロジェクトの状況を確認してください。
> 残っている作業を示し、どこから始めるべきか提案してください。

> **explore:** 招待リンクと、メールだけで行う招待を比較してください。選択する前に、
> サポートチームへの影響を説明してください。この対話はチャット内にとどめ、ファイルに保存しないでください。

> **design:** 既存の画面、ナビゲーション、文言を使って、二つの招待フローを比較してください。
> 各ステップと招待の有効期限切れの状態を示し、それぞれの案のトレードオフを説明してください。
> ビジュアルデザインだけを行い、UI は実装しないでください。

> **implement:** 招待の有効期限を 7 日間にしてください。受諾済みの招待は変更しないでください。
> 完了条件：7 日を過ぎた招待を拒否し、受諾済みの招待を変更せず、テストスイートが通ること。
> 有効期限の境界条件には TDD レベル `targeted` を適用してください。ローカルで検証し、デプロイはしないでください。

## 権限とTDDレベル

権限を持つのは利用者です（P6）。次の規則はすべてのスキルに適用されます。

- 仕様書、計画、ADR、キューの状態は実装の許可にはなりません。対話や読み取り専用のレビューも同様です。
- 一つのタスクの実装を選択しても、そのタスクが属する変更全体を許可したことにはなりません。
- エージェントは、破壊的な操作の前や、合意済みの成果、契約、TDD レベル、影響の大きい確約を変更する前に
  利用者へ確認します。
- コミット、プッシュ、公開は、利用者の許可がある場合だけ行います。許可済みの実装とリファクタリングには、
  ローカルコミットが含まれます。
- **implement** に計画だけを依頼した場合は、進め方の提案で終わり、実装は許可されません。
- **batch** が無人で進めるのは、利用者が明示的に許可した、固定のキュー項目の選択範囲だけです。
  同時割り当ては最大 4 件、5 件を選択した場合は最大 5 件で、ホストの処理能力を上限とします。
  別の回数を許可しない限り、項目ごとの修正予算は 2 ラウンドです。

実装には、TDD レベルの明示的な選択が必要です。既定値はありません。

| TDD レベル | 要件 |
| --- | --- |
| `none` | テストを先に書く必要はありません。合意した検証とリポジトリの確認は引き続き必要です |
| `targeted` | 指定した動作について、テストを先に書きます |
| `strict` | 新規または変更する動作のうち、テスト可能なものすべてについて、テストを先に書きます |

レベルは依頼の中で選択するか、プロジェクトの `docs/lusona/README.md` またはエージェントへの指示
（`CLAUDE.md` や `AGENTS.md`）に継続的な設定として記載してください。
例：`TDD: targeted for validation and persistence boundaries`。選択されるまでは、エージェントは定義と計画だけを行い、
推奨レベルを示して質問します。選んだレベルとその情報源を記録し、その手順を実行できない場合はレベルの見直しを求めます。

その権限の範囲内では、エージェントは新たな指示を待たずに作業を続けます（P7）。範囲を絞った次の作業に進み、
許可済みの作業内で測定や実験を行う際にも、新たな依頼を求めません。回答によって次の作業が変わらない質問はやめます。
ホスト標準の質問ツールがあれば使用し、推奨する回答を示します。返答がないことも、選択肢が事前選択されていることも、
同意とはみなしません。回答を待つ間は、影響を受ける作業だけを一時停止し、再開条件を示します。

利用者と話すエージェントがコーディネーターです。タスクの規模を問わず専門作業を担当エージェントに委任し、
その結果を統合して検証します。委任が禁止されているか利用できない場合は、ローカルで作業し、そのことを報告します。
割り当てについては[委任](plugins/lusona/references/delegation.md)、モデルについては
[モデルの振り分け](plugins/lusona/references/delegation.md#model-routing)を参照してください。

## 判断と見直し

合意済みの判断は、その後の作業への入力です（P3）。新たな要件、仕様、測定結果、実験結果が合意済みの判断と
矛盾する場合、エージェントは次のように対応します。

1. 判断、その情報源、矛盾、影響を受ける仮定を、返信と担当記録の両方に示します。
2. 選択肢と推奨する回答を利用者に示します。
3. 維持、一部改訂、置き換えのいずれかを利用者と合意します。判断を見直すこと自体は、変更の許可にはなりません。
4. その判断に依存する作業を再開する前に、結果を記録します。
5. 矛盾の影響を受けない作業は、既存の権限内で続けます。

記録には、各判断の履歴を残します（P4）。改訂または置き換えられた判断は本文と理由を保持し、利用者の回答の日付と
情報源を付記します。置き換えた場合は、新しい判断へリンクします。エージェントは自身の書き込み担当範囲で関連記録、
割り当て、引き継ぎを更新し、別の担当者による修正が必要な箇所を報告して、改訂に従って再開します。
置き換え済みの判断が残る記録には従わず、修正するか報告します。
[見直し](plugins/lusona/references/revisions.md)を参照してください。

追加の依頼は、現在の目標の範囲を変更し、それまでの進捗を保持します。目標を明示的に取り消すか置き換えた場合、
または両立しない目標を求めた場合にだけ、現在の目標を置き換えます。

## 根拠と完了

エージェントは実際に観測した確認結果だけを根拠に動作を報告し、未実行または失敗した確認も示します（P5）。
完了には、許可された成果とその基準、必須の確認の成功、必要な人間による受け入れが必要です。
テストの成功だけでは、人間が受け入れたことにはなりません。

- **テストを先に行った根拠。** テスト先行が必要な動作ごとに、製品コードを変更する前に意図した失敗を観測し、
  その後に成功を確認します。環境設定の失敗は、意図した失敗の根拠にはなりません。
  [TDD](plugins/lusona/references/tdd.md)を参照してください。
- **修正回数の上限。** 実質的な進展がない修正が 2 ラウンド連続したら、その失敗の修正をやめ、根拠を報告し、
  影響を受けない作業を続けます。合計 4 ラウンドに達したら、さらに修正する前に利用者へ確認します。
  バッチ内では、代わりに修正予算を適用します。[修正](plugins/lusona/references/corrections.md)を参照してください。
- **独立レビュー。** 利用者やリポジトリの規則が求める場合、または変更がセキュリティ境界、永続データ、共有する契約に
  影響する場合や、複数の担当者が連携して変更する場合は、その変更を書いていないエージェントによるレビューが必要です。
  単独でのローカル作業では満たせません。利用できなければ、要件が未充足であることを報告します。
- **研究的な作業。** **investigate** は診断の問いに答え、**measure** と **experiment** は研究的な作業を行います。
  不確実性だけを理由に研究的な作業を開始しません。依頼に含まれない研究的な作業には、利用者の明示的または継続的な
  許可と、有限の範囲および資源予算が必要です。判断の根拠はプロジェクトの `docs/lusona/evidence/` に保存します。
  [根拠](plugins/lusona/references/evidence.md)を参照してください。
- **ビジュアル資料。** **explore**、**specify**、**architect**、**design** は、配置、構造、フロー、外観に選択が
  左右される場合、2-4 案のビジュアルを提示します。UI 草案はブラウザーで開き、開けない場合は HTML の絶対パスを報告します。
  図には Mermaid コードブロックを使います。利用者が選んだ後、資料と必須要件を `docs/lusona/visuals/<record-id>/` に保持します。
  **implement** は各必須要件の状態を報告し、**review** は各要件を充足、未充足、未確認として報告します。
  [ビジュアル](plugins/lusona/references/visuals.md)を参照してください。

## 記録と再開

エージェントは引き継ぎや完了の前に、後続作業が依存する重要な成果を、依頼されなくても保存します。
判断、合意、根拠、調査結果、引き継ぎ、対話の整理結果などが対象です。後続作業が依存しない説明や状況報告には
記録は不要です。保存が禁止されている場合は、何を保存しなかったかを報告します。

| 作業 | プロジェクトの `docs/lusona/` 内の記録 |
| --- | --- |
| 仕様書が必要な変更 | `specs/<change-id>.md` と `work.md` の行 |
| 仕様書のない直接の実装やリファクタリング | `notes/<change-slug>.md` |
| 調査、測定、実験 | ノートと `evidence/` 内の記録 |
| 影響の大きいアーキテクチャ判断 | `adr/<YYYYMMDD>-<decision-slug>.md` |
| プロダクト概要と機能マップ | `product.md` |
| バッチ | `batches/<batch-slug>.md` |

次の四つの場合には、仕様書とキューの行が必要です。規模は判断基準ではありません。

- **specify** のように、スキルが仕様書で変更を定義する場合。
- 利用者が仕様書や追跡を求めた場合。
- その変更の仕様書がすでにある場合。
- 変更の影響によって独立レビューが必要な場合。

キューの状態は Ideas、Ready、Doing、Review、Done です。どの状態も実装の許可にはなりません。
Icebox は、保留した行を置くキューの区分です。保留した行もキューの状態を保持します。
[キュー](plugins/lusona/references/queue.md)を参照してください。

各担当記録は、目標、判断、権限、TDD レベルとその情報源、根拠、不確実な点、修正回数、阻害要因、担当範囲、
次の作業を含む最新の引き継ぎを一つ保持します（P2）。ホストがコンテキスト使用量を報告する場合、40% で引き継ぎを
準備し、50% に達する前に完成させます。再開時は残っている記録と作業ツリーを読み、権限または次の作業を変える事実だけを
利用者に尋ねます。許可は引き継ぎをまたいで有効です。突然の中断で保存できなかった場合、保存済みの中間状態があるとは
報告しません。以前のプラグインバージョンの記録も有効で、元の場所で更新します。
[保持](plugins/lusona/references/retention.md)と[ファイル](plugins/lusona/references/files.md)を参照してください。

再開するには、**status** で残作業を確認するか、続ける作業を指定してください。

> 保存済みの調査結果に基づき、招待の有効期限の調査を続けてください。記録された再現手順を現在のビルドで
> 確認してください。本番コードの動作は変更しないでください。

## 返信と次の作業

すべての作業の返信は、同じ形式で終わります（P8）。挨拶や了解の返答は対象外です。状態は **✅ 完了**
（依頼範囲を達成）、**🔄 進行中**（許可済みの作業を継続）、**❓ 入力が必要**（前提条件が不足）、
**⏸ 一時停止**（影響を受ける作業が、明示した前提条件を待っている）のいずれかです。
状態は返信の状況を表し、キューの状態ではありません。次は仮の返信例で、作業を実施した根拠ではありません。

> **Result:** ❓ 入力が必要：実装を始める前に TDD レベルを選んでください。仕様書と受け入れ基準は記録済みです。
>
> **Evidence:** 確認は未実行です。変更は定義済みで、未実装です。
>
> | Next action | Owner | Needs | Authority |
> | --- | --- | --- | --- |
> | `none`、`targeted`、`strict` から選ぶ。パーサーの変更には `targeted` を推奨 | 利用者 | 記録済みの仕様書 | TDD レベル未選択 |

- 担当は利用者、コーディネーター、または名前を明示したスキルです。Authority 欄には `Authorized` または不足する権限を示します。
- 作業を阻む判断や承認を先に示します。影響の大きい判断を行った場合は **Decisions:** を、問題が残る場合は **Open issues:** を加えます。
- 範囲内の作業が完了していて、後続作業が合意済みの成果に役立つ場合は、その作業を提案し、不足する権限を示します。
  作業が残っていなければ、`**Next action:** None for this request` と記し、その理由を一文で示します。
- 別のセッションへの継続指示は、表の下の引用ブロックに置きます。
- 利用者の書式指定とホストの制約を優先します。ただし、成果、根拠、状態、次の作業は残します。
  [完了例](plugins/lusona/references/completion.md)を参照してください。

## インストール

使用するホストを選んでください。公開リポジトリ [lusona/ai-skills](https://github.com/lusona/ai-skills)
から HTTPS でインストールします。ダウンロードに GitHub の認証情報は不要です。

### Antigravity

GitHub から直接インストールします。

```bash
agy plugin install https://github.com/lusona/ai-skills.git
```

この URL は、リポジトリルートのマニフェストから Lusona をインストールします。App とスタンドアロン IDE では、
この CLI によるグローバルインストール後に **Customizations** を確認します。
[Antigravity のインストールガイド](INSTALL.md#antigravity)に、ローカルチェックアウト、ポータブルパッケージ、
更新、削除、検証範囲を記載しています。Lusona 1.4.0 を対象に、Linux 上の Antigravity CLI 1.4.12 で
GitHub インストールを確認した記録があります。App と IDE の対話動作は未検証です。

### Claude Code

```bash
claude plugin marketplace add https://github.com/lusona/ai-skills.git
claude plugin install lusona@lusona-ai-skills --scope user
```

### Codex

```bash
codex plugin marketplace add https://github.com/lusona/ai-skills.git
codex plugin add lusona@lusona-ai-skills
```

### Cursor

**Customize > From GitHub Repository** を開き、`https://github.com/lusona/ai-skills` を入力して、
プロジェクトまたはユーザー用に **Lusona Skills** をインストールします。Agent チャットで `/` を入力すると、
Lusona のスキルを探せます。[Cursor のインストール手順](INSTALL.md#cursor)に、現在の Cursor のドキュメントへの
リンクとテスト状況を記載しています。

### Xcode

Xcode 27 で **Settings > Intelligence > Agents > Plug-ins > Add Plug-in** を開きます。
**Add from URL** を選び、`https://github.com/lusona/ai-skills` を入力して、インストールする Lusona のスキルを
選んでください。設定、ローカルからのインポート、バージョンの詳細は、
[Xcode のインストール手順](INSTALL.md#xcode)を参照してください。

インストール後は、プロジェクトで新しいセッションを開始してください。ローカルチェックアウトからのインストール、
ポータブルパッケージ、更新、削除については、[インストールガイド](INSTALL.md)を参照してください。
カタログの取得元は、ローカルチェックアウトか GitHub のどちらか一つを選びます。

## 開発

ワークフローの正式なソースは `plugins/lusona/` にあります。利用先プロジェクトのデータは、そのプロジェクトの
`docs/lusona/` に置きます。空のキュー構造は `plugins/lusona/templates/work.md.template` にあります。

プラグインの記録用ヘルパーは Bash または PowerShell を使います
（[実行環境の要件](INSTALL.md#requirements)）。Python 3 はパッケージ作成と Python による評価にだけ必要で、
プラグインの利用には不要です。

```bash
claude plugin validate plugins/lusona
claude plugin validate .claude-plugin/marketplace.json
python3 scripts/package.py
```

パッケージ作成ツールは、ホスト標準のマニフェストの名前とバージョン、リンク、カタログのパス、収録ファイルを確認します。
すべてのネイティブマニフェストは同じバージョンを使う必要があります。出力先はリポジトリ内の `tmp/lusona-package/` で、
既存の出力ディレクトリは上書きしません。別のビルドには `--output tmp/<new-directory>` を指定してください。
インストールやパッケージ作成によって、プロジェクトの記録を初期化することはありません。

各 `SKILL.md` の全タスク共通規則と返信形式は、リポジトリの `shared/` ディレクトリから生成します。
変更はそこで行い、`python3 scripts/sync_shared.py --source shared
plugins/lusona` を実行してください。`--check` を加えると、書き込まずに検証できます。
